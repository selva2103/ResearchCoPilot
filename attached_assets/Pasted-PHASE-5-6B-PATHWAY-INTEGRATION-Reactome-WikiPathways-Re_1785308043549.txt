NON-NEGOTIABLE ARCHITECTURAL CONSTRAINTS
 
 
- 
 

 
`pathwayId` is the canonical identifier everywhere internally (e.g. Reactome's `R-HSA-109581` or WikiPathways' `WP254`) — `pathwayName` is display-only, never used as a key.
 
 
- 
 

 
**The audit — not prior expectations — determines the production retrieval source.** Do not pre-assume Reactome as primary; Step 1 must decide this from real evidence.
 
 
- 
 

 
**Duplicate pathways across sources:** if the same biological pathway appears in both Reactome and WikiPathways (or whichever sources are used), do NOT attempt to merge them or infer equivalence between their IDs. Preserve source attribution and display each source's entry separately, even if a researcher would recognize them as "the same" pathway conceptually. Only treat two entries as one if their canonical IDs are literally identical (which will not occur across different databases) — never merge based on name similarity or inferred equivalence.
 
 
- 
 

 
**Identifier immutability:** this phase consumes `geneId` and `organism` already resolved upstream by Phase R / Gene Explorer. It must NEVER independently resolve gene identity — no new symbol-to-ID lookup, no new ambiguity handling. If the GeneID passed in doesn't produce results from a source, that's an empty result, not a trigger to re-resolve anything.
 
 
- 
 

 
This is the first genuinely new external host in this project (not NCBI Entrez family) — unless Step 1's reuse-first check (Step 1.0) finds this data already available in Gene XML, in which case no new host is needed at all. If a new host is required, build a new, minimal, dedicated client — do not force it through the existing NCBI-specific client — but apply the same rate-limiter/retry/ cache-separation philosophy already established, scoped independently to this new host.
 
 
- 
 

 
No pathway diagram/visualization rendering — membership listing only. This is the most likely feature-creep temptation in this phase, since both Reactome and WikiPathways offer diagram image endpoints — do not embed them.
 
 
- 
 

 
No KEGG integration under any circumstance in this phase.
 
 
- 
 

 
No LLM-generated interpretation of pathway relevance.
 
 
- 
 

 
Never fabricate a pathway membership — empty means empty.
